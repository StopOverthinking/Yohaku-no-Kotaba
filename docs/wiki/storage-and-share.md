# Storage And Share

## 저장 철학

기능별로 필요한 최소한만 저장한다. 학습 세션과 결과는 각 기능의 수명주기를 벗어나 오래 끌고 가지 않는다.

## 일반 학습 설정 저장 규칙

2026-10-02 수준별 병합으로 보관 처리한 `AbsoluteVerb`의 저장된 단어장 선택은 N5로 정규화한다. 보관 단어장과 소유 단어·용법·예문 ID는 런타임 조회에 남아 기존 진행 세션·undo·즐겨찾기·복습 기록을 그대로 읽는다. 이번 병합은 저장 스키마를 바꾸거나 프로필을 합치지 않는다. 수준별 기존 숫자 범위와 순서는 그대로이며 신규 참조만 뒤에 추가한다.

- `preferencesStore.learnDefaults`에 일반 범위와 필수 포함 범위 토글·구간 목록을 함께 저장한다.
- 예전 저장값에 필수 범위 필드가 없으면 토글 꺼짐과 빈 목록을 기본값으로 보완한다.

## 공유 규칙

앱 백업은 `jsp-react:` 기반 일반 앱 데이터만 다룬다.

- 방식: 클립보드, 파일, QR
- 복원: 확인 모달 후 기존 `jsp-react:` 데이터를 교체하고 새로고침
- 제거된 기능의 레거시 키는 내보내기와 가져오기에서 제외한다.

## QR 규칙

- 앱 백업 QR은 일반 백업 텍스트를 분할해 전송한다.
- 큰 payload는 gzip 압축을 시도하고, 필요하면 여러 프레임으로 나눈다.
- 한 프레임에는 Base64 URL 텍스트를 최대 400자만 담아 QR 모듈 밀도를 낮추고 원거리 인식성을 확보한다.

## 문장 학습 상태 v2/v3

용법 ID와 버전을 키로 다음 복습일, 간격 단계, 실패 횟수/날짜 수, 마지막 학습일과 당일 시도 횟수(첫 시도를 제외한 재학습 횟수 계산용), 예문별 노출·실패·힌트 횟수를 저장한다. 내부 추천 수준과 초기 측정 단어 ID 최대 20개를 함께 저장한다. 전체 학습 행동 로그는 보관하지 않는다.

새 학습 상태의 점수는 N5~N4 수준을 가정한 16점이고 측정 단어 ID는 빈 배열이다. 콘텐츠·선택 범위와 무관하다. 기존 저장값은 그대로 읽으며, 측정 단어와 용법 프로필이 모두 없는 상태에서 첫 세션을 시작할 때만 고정 초기값을 적용한다. 기존 학습 점수·프로필·복습일·진행 세션·undo의 저장 형식은 바꾸지 않는다.

진행 중 세션은 카드의 용법/예문 버전, 공개·힌트 상태, 출제 범위와 순서, 재학습 큐를 보존한다. 연속 undo는 변경된 프로필과 직전 세션의 변경분만 저장한다. 출제 범위와 카드 배열의 공통 구간을 반복 직렬화하지 않아 큰 범위에서도 저장 용량을 줄인다. 판정과 세션 이동은 같은 저장값에 반영하므로 쓰기 실패 시 진행하지 않는다. DB 트랜잭션 내부의 저장 토큰 비교로 오래된 탭의 덮어쓰기를 막는다.

공유 백업에 v2 키를 포함하며 복원 전 형식을 검증한다. 복원 쓰기가 실패하면 기존 값으로 되돌리며, 모든 쓰기가 성공한 뒤에만 이전의 불필요한 키를 제거한다. 파싱 실패 원본은 지우지 않는다. 옛 스마트 복습 키/IndexedDB는 재사용하지 않는다. 초기 부팅에서는 hydrate가 완료된 뒤 라우트 화면을 표시해 복원 전 리다이렉트를 막는다.

## 2026-09-29 단일 학습 전환

시험·활용형·게임 및 예전 단어 카드 모드의 저장 코드는 제거했다. 기존 문장 학습 v2 프로필·세션·undo는 같은 키와 스키마로 읽는다. 제거된 모드의 기존 브라우저 값은 자동 삭제하지 않으며 읽거나 실행하지 않는다. 백업 입출력에서는 `exam-*`, `conjugation-*`, `game-*`, `learn-session` 키를 제외하고, 옛 시험·게임 백업 변환도 제거했다.

문장 학습 완료 시 `lastScoreChange`에 시작 점수·종료 점수·완료 시각 한 건만 함께 저장한다. 오래된 v2 값에 이 필드가 없어도 그대로 읽는다. 세션 첫 판정 직전 undo 스냅샷이 시작 점수이므로 새로고침·연속 되돌리기 후에도 차이가 정확하다. 완료 전체 화면은 메모리 상태지만 최근 점수 변화는 새로고침과 백업 복원 뒤에도 설정에서 볼 수 있다.

## 복습 간격 정책 버전

정책 정의·날짜·판정은 `contextReviewPolicy.ts`, 저장 형식 검증과 이전은 `contextPersistence.ts`에 둔다. 저장 파서는 엔진에 의존하지 않는다. DB·localStorage 키와 상태 v2/v3는 유지하며 현재 정책은 v4다.

`scheduleVersion: 4`와 용법별 선택적 `mastered` 불리언을 저장한다. 처음부터 맞힌 단어는 3·7·30·90일, 오답이 있으면 1·2·3·5·8·14·21·36·48·72·96·120일 간격을 따른다. 각 흐름의 마지막 예정 복습까지 맞혀야 완료 표시를 저장한다. due를 가짜 먼 날짜로 바꾸거나 프로필을 삭제하지 않는다. 완료는 모든 학습 범위·오늘 복습 수·다음 날짜·복습 목록에서 제외한다. undo·DB·백업에 완료 상태를 함께 보존한다. 구 클라이언트는 정책 v4를 거부하므로 이전 규칙으로 저장하지 못한다.

v1~v3의 예약일·누적 횟수·진행·undo를 보존한다. 오답 없는 프로필은 v2/v3의 15단계를 유지하고 v1의 8단계만 같은 기본 일수로 옮긴다. 오답이 있으면 옛 기본 간격을 1회 오답 기준(`max(1, round(간격 / 1.25))`)으로 계산한 뒤 그 이하의 가장 큰 새 간격 인덱스(0~11)로 옮긴다. 모든 활성/undo 프로필을 함께 변환하며 마지막 단계도 기존 예약 복습을 마친 뒤 완료한다. 별칭 원본 보관 프로필은 역사적 값으로 변경하지 않는다. 알 수 없는 정책 버전·범위 밖 단계·불리언이 아닌 완료 표시는 거부하고 원본을 보존한다. 반복 로드는 다시 변환하지 않는다.

기존 IndexedDB를 읽을 때 정책 이전이 필요하면 스냅샷에 이전 필요 표시를 붙인다. hydrate는 헤더·전체 활성 프로필·undo를 한 트랜잭션에 저장한 뒤 화면을 연다. 이전 전후 프로필 참조가 같아도 모든 활성 프로필을 쓰므로 v4 헤더만 저장하고 옛 단계를 남기는 부분 이전이 없다. 실패·탭 충돌에서는 원본과 저장 토큰을 유지한다.

사용자 확인 삭제는 상태의 선택적 `excludedWordIds` 배열에 저장한다. 프로필·점수는 유지하고 복습 목록·개수·날짜·학습 후보에서 해당 단어 전체를 제외한다. 같은 용법의 별칭 ID도 함께 제외해 아직 연결되지 않은 옛 진행 세션의 재학습·undo로 다시 노출되지 않게 한다. 연결 경계에서는 대표 ID로 정규화한다. 삭제는 DB 저장 완료 후 화면에 반영하며 실패하면 목록을 유지하고 재시도한다. 백업 왕복과 새로고침에서 제외를 유지하고 일반 카드 undo는 이 배열을 복구하지 않는다.

복습 목록에서 확인한 학습 기록 초기화는 `contextAsyncStore.resetLearning()`으로 현재 저장 토큰을 비교하는 기존 단일 트랜잭션을 사용한다. 모든 활성 프로필을 삭제하고 진행 세션·undo·완료·복습 제외·최근 점수 변화와 메모리 결과를 비운다. 수준은 16점·측정 단어 0개로 되돌리고 revision은 기존 값에서 증가시킨다. 별칭 보관 원본의 학습 기록도 비우며 현재 연결 그룹의 빈 메타데이터를 새로 생성해 재로드에서 과거 진행이 돌아오지 않게 한다. DB·이전 완료 표시는 유지하며 설정·즐겨찾기와 보존용 이전 원문은 건드리지 않는다. 실패나 탭 충돌에서는 기존 화면·DB 기록·메모리 결과를 유지한다. 초기화 후 내보내기는 비워진 현재 상태를 사용하고 일반 undo로 초기화 전 기록을 복구하지 않는다.

지원하지 않는 숫자 학습/정책 버전은 `UnsupportedContextVersionError`로 구분하고 undo 압축을 해석하기 전에 거부한다. 백업 파싱은 지원하는 현재 envelope(`jsp-react-backup-v1`), 숫자 1의 옛 envelope와 버전 없는 기존 항목을 유지하며 그 밖의 명시적 버전을 거부한다. 손상된 기록은 형식 오류로 표시한다. 학습 키가 빈 문자열이어도 설정만 부분 복원하지 않는다. 복원 journal·설정·DB 쓰기를 시작하기 전에 검증하며 오류 때 기존 학습·설정을 보존하고, 다른 백업 선택이나 기존 앱 사용으로 돌아갈 수 있다.

오답 이력이 있으면 항상 새 12단계 흐름으로 계산한다. 누적 실패 수는 지우지 않지만 간격을 추가 단축하는 데 사용하지 않는다. 같은 날의 추가 판정은 점수·실패 수·실패 날짜·일정·완료 상태를 바꾸지 않는다. 노출/시도·힌트·같은 세션의 재학습 큐는 계속 저장한다. 별칭 병합은 기존 프로필 모두가 완료된 경우에만 완료를 유지하며 미완료 복습을 숨기지 않는다. 서로 다른 흐름을 병합하면 실제 간격 중 짧은 쪽 이하의 오답 단계로 대응시킨다.

## 대량 확충용 저장소 (2026-09-30, 앱 연결 완료)

`share/contextBackup.ts`는 학습 DB와 localStorage 설정을 함께 복원하는 조정 계층이다. 복원 전 설정을 DB에 기록하고 학습 쓰기를 잠근다. 새 설정을 적용한 뒤 새 학습 상태와 복원 기록 제거를 같은 DB 트랜잭션으로 확정한다. 중단되거나 확정 전에 실패하면 복원 기록으로 이전 설정을 되돌린다. 되돌리기 자체가 실패하면 복원 기록을 유지해 다음 부팅 때 재시도한다.

Web Locks로 살아 있는 다른 탭의 복원을 기다린 뒤 중단 복구·내보내기를 수행한다. 이를 지원하지 않는 환경에서는 안전하지 않은 병행 복원을 실행하지 않고 오류를 반환한다. UI 연결 시 부팅 hydrate 전에 `recover()`를 호출하고, 내보내기는 `snapshot()`의 일관된 상태를 사용한다. 외부 키는 건드리지 않으며 복원은 `jsp-react:` 키만 다룬다.

`contextAsyncStore.ts`는 비동기 저장 완료 이후에만 화면용 상태를 갱신하는 학습 스토어다. 중복 hydrate는 하나로 합치고, 진행 중인 저장 뒤에 hydrate를 실행한다. 저장 중 새 판정·힌트·undo는 중복 처리하지 않는다. 저장 실패는 현재 카드와 기록을 유지하며 재시도할 수 있다. 다른 탭 충돌이나 읽기 실패는 다시 hydrate하기 전까지 새 세션 시작을 막는다. 기본 `useContextStore`가 이 스토어를 사용하며 학습 화면은 판정·시작·undo 저장 완료를 기다린다. 저장 중 판정·힌트·이전 카드 버튼은 비활성화한다.

`contextDatabase.ts`에 별도 IndexedDB `yohaku-context-learning`의 트랜잭션 계층을 구현했다. `contextBrowserPersistence`가 부팅에서 중단된 복원을 먼저 정리한 뒤 기존 v2 데이터를 이전한다. providers는 비동기 hydrate 완료 뒤 라우트 화면을 표시한다.

- `profiles`에는 용법별 기록을 따로 저장한다. 변경하지 않은 프로필 객체의 참조를 유지하는 엔진 계약을 이용해 바뀐 항목만 쓴다.
- `meta`의 현재 상태에는 고유 저장 토큰, 프로필 수, 수준·진행 세션·압축 undo를 저장한다. 프로필 변경과 같은 트랜잭션으로 확정한다.
- 토큰 비교와 쓰기를 하나의 readwrite 트랜잭션 안에서 수행해 다른 탭의 같은 revision도 덮어쓰지 않는다. 요청 하나의 성공이 아니라 트랜잭션 완료 후에만 성공으로 반환한다.
- 최초 이전은 원본 v2 문자열을 `original-local-v2`에 함께 보존하고 다시 읽어 검증한다. 이 계층은 localStorage 원본을 제거하지 않는다. 반복 이전은 이미 갱신한 DB 기록을 초기 상태로 돌리지 않는다.
- 손상된 입력과 불완전한 DB는 오류로 반환하고 원본을 보존한다. 저장 실패는 프로필·진행·undo 전체를 함께 취소한다.

앱 연결 후에도 옛 탭과의 이전 경합, 백업 내보내기·복원과 기존 브라우저의 실제 이전을 별도로 검증해야 한다. `fake-indexeddb`는 테스트 전용 의존성이며 앱에 번들링하지 않는다.

`contextRepository.ts`는 이 DB와 기존 localStorage 사이의 연결 계층이다. DB에 이전 원본을 보존하고 검증한 뒤 기존 키를 작은 이전 완료 표시로 바꾼다. 이전 과정에서 원본이 달라지면 양쪽을 보존하고 충돌을 반환한다. 표시 쓰기가 실패하면 원본 문자열을 그대로 두어 재시도할 수 있다. 이미 이전했다는 표시만 있고 DB가 없을 때는 빈 기록을 만들지 않는다. 명시적인 유효 백업 복원으로만 빠진 DB를 재생성한다.

기존 탭은 이전 완료 표시를 v2 기록으로 읽을 수 없으며 기존 문자열 비교도 실패하므로 옛 상태를 저장할 수 없다. 새 탭은 쓰기 전과 트랜잭션 내부, 완료 뒤에 표시를 확인한다. 내보내기는 DB의 일관된 최신 스냅샷을 현재 v2/v3 형식으로 직렬화하고, 학습 기록 복원은 하나의 트랜잭션에서 교체한다. 공유 화면은 `appBackup.ts`에서 조정 계층의 스냅샷·복원을 호출한다. 내보낸 v2 문자열에 이전 완료 표시가 섞이지 않는다.

실제 브라우저의 이전·복원·키보드·터치 검증은 자동 테스트와 별도로 수행한다. QR이 압축 뒤에도 64장을 넘으면 SVG 대량 생성을 중단하고 파일 저장 버튼을 제공한다. 실패한 QR 생성을 성공으로 표시하지 않는다.

## 동일 의미 예문의 삭제와 진행 세션

`content/learn/example-pruning/*.json`은 삭제 전후 해시, 삭제한 예문 원문과 순서, 같은 의미의 잔존 예문 ID를 보관한다. 생성 시 검증된 매핑만 `data/exampleRetirements.ts`로 전달한다. 단어·용법 ID와 버전은 바꾸지 않으며 새 저장 스키마는 필요하지 않다.

`reconcileRetiredExamples`가 hydrate에서 현재 세션과 모든 undo 세션의 카드 참조를 정정한다. 대체된 현재 카드의 공개·힌트 상태는 초기화하지만, 과거 예문 노출과 undo의 프로필·점수 스냅샷은 원래 ID로 보존한다. 대체 예문을 이미 본 것으로 세지 않는다. 기존 백업을 복원해도 같은 경로를 거치며 반복 실행은 변경을 만들지 않는다. DB 저장 실패 시 이전 저장값을 유지하고 다시 hydrate할 수 있다. 검토된 대체가 없는 콘텐츠 변경은 기존 오류 안내를 유지한다.

## 검토된 동일 용법의 기록 연결

서로 다른 핵심 뜻의 중복 항목은 수준별 대표를 선택하더라도 기록을 연결하지 않는다. 참조 승인에 모든 같은 정규형 원본 해시를 검토한 선택 근거를 남기며, 원본 프로필·예정일·예문 기록은 각각 보존한다. 대표에 새로 추가한 용법도 별도 새 프로필을 사용한다.

`legacy/active-aliases.json`에 명시한 그룹만 활성화한다. 독립 검토의 `equivalent-core-usage` 승인, 현재 단어·용법 전체 해시, ID/버전 일치를 생성 및 감사에서 확인한다. 같은 표기라도 의미 범위가 더 넓으면 기록 이전을 보류한다. 첫 활성 그룹은 複雑이었으며 최종27그룹을 활성화했다. 기존 정의를 변경하지 않고 현재 해시 검증을 통과한 그룹만 추가한다.

세션과 undo가 없는 hydrate 또는 세션 완료·파기·새 시작 경계에서 한 트랜잭션으로 이전한다. 진행 중인 옛 카드와 undo는 그대로 유지한다. 원본 프로필과 당시 수준은 `aliasMigrations`에 보관하며 백업에도 포함한다. 활성 프로필은 대표 용법 하나로 연결하고 예정일은 더 이른 날짜, 단계는 더 낮은 단계, 실패 수는 합산하지 않은 최댓값을 사용한다. 기존 예문별 기록을 보존하되 보지 않은 대표 예문의 노출 횟수로 옮기지 않는다. 점수 값은 유지하고 초기 측정 단어 ID만 중복 제거한다.

이전이 적용된 상태만 스키마 `version: 3`이 된다. 외부 백업 키는 기존 `jsp-react:context-learn-v2`를 유지하며 옛 v2 백업도 읽는다. 옛 클라이언트는 v3를 거부하고 이전 저장 토큰으로 쓰기도 실패한다. 이미 이전한 그룹 정의가 달라지거나 사라지면 자동 초기화하지 않고 원본을 보존하며 오류를 표시한다. 이후 그룹 변경에는 별도 이전 설계가 필요하다. 저장 실패 시 이전 상태를 유지하고 재시도한다.

최종4,861개 규모 실제 브라우저에서27그룹/61원본 프로필의 안전한 세션 경계·undo·원본 보관·이른 예정일/낮은 단계·비합산·반복 이전·백업 왕복을 확인했다. 消す/違う의 다른 핵심은 분리하며 새 용법에 원래 숙련도를 복제하지 않는다. 전체 코퍼스 합성 프로필로500저장/500undo 및 전량 백업을 검증했다. 상세는 `content/jlpt/benchmarks/2026-10-01-browser-scale.md`를 따른다.
