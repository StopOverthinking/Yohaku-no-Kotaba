# App Shell

## 목적

메인 앱의 공통 프레임, 라우팅, 홈 진입 구조를 설명한다.

## 진입점

- 메인 부팅: `src/main.tsx`
- 라우터: `src/app/router.tsx`
- 셸: `src/app/App.tsx`
- providers: `src/app/providers.tsx`
- 홈: `src/features/home/HomePage.tsx`

## 핵심 상태

- 라우터는 `createBrowserRouter` 기반
- `AppProviders`가 앱 시작 시 여러 스토어 `hydrate()`를 호출
- 홈은 각 세션 스토어의 현재 상태를 읽어 배너를 표시
- 앱이 백그라운드에서 재생성될 수 있으므로 진행 중 세션은 기능별 저장소에서 복구한다.

## 라우트 구조

- 메인 앱은 `/` 하위 중첩 라우트
- 에디터 전용 라우트와 별도 HTML 진입점은 제거했다. `/editor`를 포함한 알 수 없는 경로는 홈으로 이동한다.

## 라우트 전환 규칙

- 효과 축소 조건이면 즉시 교체
- 일반 조건이면 현재 화면이 짧게 exit 후 다음 화면 enter
- 전환 효과는 `opacity + y`만 사용
- 목록(`/list`)이 출발지나 도착지인 전환은 즉시 교체한다. 목록은 큰 카드 표면을 가질 수 있어 전체 페이지를 전환 애니메이션 레이어에 올리지 않는다.

## 홈 구조

홈은 세 가지 역할을 가진다.

- 잔여 세션/결과를 배너로 복구
- 목록/학습/공유의 1차 허브
- 학습 버튼은 `/learn` 설정으로 직접 이동
- 홈 하단 정보 아이콘은 `sources.html`의 사전·수준 분류·AI 작성/검토·라이선스 출처로 연결한다.

## 홈에서 바로 보여주는 상태

- 진행 중 일반 학습
## UI 규칙

- 홈 카드 설명은 짧게
- 중요한 이동은 큰 카드
- 서브메뉴는 필요할 때만 펼침
- compact 환경에서도 같은 정보 구조 유지

## 수정 시 주의점

- 새 feature를 추가하면 라우터와 홈 진입 지점을 함께 조정
- 새로운 스토어가 hydrate 필요하면 `AppProviders`에 추가
- 전역 애니메이션을 무겁게 만들지 말 것
- 새 진행형 세션을 추가하면 백그라운드 복귀/페이지 재생성 후 복구 가능한 저장 경계를 함께 정할 것
