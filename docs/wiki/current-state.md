- 학습 개수 설정 근처에 선택 범위의 오늘 복습 단어 수를 표시한다. 복수 용법과 별칭은 중복 제거하며 양수일 때만 요청 문구를 표시한다.

## N5~N1 실용 어휘 확충 완료

N5 599개 · N4 648개 · N3 1,727개 · N2 1,056개 · N1 831개, 고유 수록 **4,861개**. 실제 신규4,114개와 기존 ID 재사용747개를 구분한다. 동일 의미 예문 정리 후 수준별 선택 예문5,083개, 앱 전체5,635단어·5,658용법·5,874예문이다.

- 사용자 지시로 목표를 약5,000개로 조정했다. 고정 할당량 없이 현재 원장 해시에 연결된 Astra high 독립 선정 승인을 완료했다. 최종 누락0·자동 유사쌍0, 남은 반복 도입1/결말10그룹은 실제 장면을 독립 검토했다. 기존 분류47파일 구조 오류0, 원고207부분 출처/승인/반영 대기0. 전량233검사 통과 뒤 최종 규모의 관련54검사와 마지막 예문 정정 후11검사를 재확인했다. 실제 브라우저 전량 프로필·500판정/500undo·백업·128묶음·27그룹 이전을 통과했다. 모바일 Chromium 에뮬레이션 카드/undo p95 65.6/62.4ms, N3 검색120.1ms, 초기5회656.7ms/재방문25회129.1ms. 실제 휴대폰/Safari 성능을 주장하지 않는다.
- 기존 확충에서 GPT-6.1 Sol medium이 단어·예문을 함께 작성하고 Astra high가 전량 검토·문제 수정했다. 이후 2026-10-02 사용자 지시에 따라 같은 의미의 복수 예문은 대표1개로 정리했다. 의미 차이가 있는 예문과 별도 용법 ID는 보존했다. 모든 수록 용법에 뜻·읽기·힌트·차이 설명·검토 예문을 채웠다.
- 27개 동일 핵심 그룹만 기록을 보수적으로 연결한다. 원본 기록 보관·더 이른 예정일·낮은 단계·횟수 비합산·진행 세션/undo의 안전한 경계를 유지한다. 消す·出来る·違う의 다른 핵심은 숙련도를 합치지 않고, 추가 용법은 미학습으로 시작한다.
- 미공개 중복 수준 참조2개(AbsoluteVerb_162 いる, AbsoluteVerb_239 見付ける)만 별도 독립 승인·현재 원격 공개 기준 대조·전후 이력으로 철회했다. 원본 ID·콘텐츠·프로필 및 나머지 상대 순서는 보존했다. 일반 가져오기의 추가 전용 규칙은 바꾸지 않았고 기존 공개 JLPTN3_115 참조를 유지했다. 이 좁은 복구를 일반 삭제 권한으로 사용하지 않는다.
- 선정은 생활·업무·일반 독해를 위한 실용 범위다. N3·명사 비중이 높으며 공식 JLPT 전체 목록·모든 사전 뜻·모든 문법 기능의 완전 수록은 아니다. 미선정あの 지시연체사는 별도 초안으로 보존하며 기존 감탄사 뜻을 덮어쓰지 않는다.

상세: [최종 선정](../../content/jlpt/final-selection-review.md), [최종 브라우저 검증](../../content/jlpt/benchmarks/2026-10-01-browser-scale.md), [작성 시간 측정](../../content/jlpt/benchmarks/2026-10-01-efficiency.md), [현재 집계](../../content/jlpt/progress.json). 과거 단계의 미완료/구모델/목표 수량은 [진행 이력](../../content/jlpt/implementation-progress.md)의 해당 날짜 기록이며 현재 상태를 대신하지 않는다.

## 저장·게시 계약

학습은 변경된 프로필·진행 세션·undo를 IndexedDB의 단일 트랜잭션에 저장한 뒤 화면을 바꾼다. 기존 v2 원문을 보관하고 작은 이전 표시를 남기며, 옛 탭·revision 충돌에서는 덮어쓰지 않는다. v2/v3 앱 백업은 설정과 학습을 함께 복원하고 실패·중단 복구를 지원한다. 64장 초과 QR은 파일 백업으로 안내한다.

Pages CI는 전체 테스트·콘텐츠 감사·현재 선정의 `jlpt:audit --require-target`을 통과한 버전만 게시한다. `release.json`의 commit과 indexSha256로 실제 공개 버전과 HTML을 대조한다. 로컬 검증/콘텐츠의published 원장은 웹 게시 성공과 다르다. 사용자가 요청한 완료 후 Git push → 실제 게시 확인 → 비강제 컴퓨터 종료 순서를 따른다.
