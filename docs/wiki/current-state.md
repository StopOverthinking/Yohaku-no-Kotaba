# Current State

작성 기준: 2026-10-07. 현재 제공 기능과 유지할 계약을 정리한다. 날짜별 구현·검증·승인 기록은 [변경 전 원문 이력](current-state-history-2026-10-06.md)에 보존한다.

## 현재 제공 기능

- 목록, 문장 빈칸 학습, 복습 목록, 즐겨찾기, 설정과 앱 백업을 제공한다. 홈에서 학습 설정으로 바로 이동한다. 상세 흐름은 [앱 셸](features/app-shell.md), [목록](features/list-mode.md), [학습](features/learn-mode.md)을 따른다.
- 선택 가능한 단어장은 기존 기본 2개(`jlpt-n3`, `set-2`)와 N5~N1 실용 단어장 5개다. `AbsoluteVerb`는 보관 처리되어 선택에서 제외하지만 원래 ID·소속·콘텐츠·진행 기록 조회를 유지한다. 저장된 선택은 N5로 정규화한다.
- 학습 카드는 목표어 앞뒤 후리가나, 카드 전체 정답 공개, 독립 힌트와 최대 2개의 비슷한 단어, 마지막 학습일 배지를 표시한다. 비교어는 표제어·정답과 한자를 공유하지 않으며 안전한 후보가 없으면 비교어 줄을 생략한다. 전체 5,658용법의 선택 자료와 대비 경로를 조사하며 [전후 조사 기록](../../content/learn/hint-answer-leakage-review.md)을 보존한다. 키보드·마우스·터치, 같은 세션의 모름 재학습, 연속 undo와 새로고침 재개를 지원한다.
- 별도 에디터 앱과 시험·활용형·게임·예전 단어 카드 모드는 제거했다. `src/features/vocab/editor-data`는 역사적 경로명을 유지한 데이터 원본이다. `탭 매치 러시`는 미완이므로 이 위키의 설계 범위에서 제외한다.

## 학습·저장 계약

- 현재 복습 정책은 v4다. 처음부터 정답은 3·7·30·90일, 오답 이후는 1·2·3·5·8·14·21·36·48·72·96·120일이다. 마지막 예정 복습도 맞혀야 완료하며, 하루 첫 판정만 점수·실패 횟수·일정에 반영한다. 최초 점수는 16점이며 첫 20개 서로 다른 단어의 실제 응답으로 보정한다.
- 예정일 전·완료·사용자 삭제·오늘 학습한 단어는 새 세션에서 제외한다. 단어장·즐겨찾기·필수 범위·다른 용법으로 우회하지 않는다. 같은 세션의 모름 재학습은 유지한다. 복습 목록 삭제는 확인 후 단어 전체와 별칭을 제외하며 기존 점수·프로필을 보존한다.
- 복습 목록의 초기화 아이콘은 앱 내부 플로팅 경고로 확인한 뒤 모든 학습 기록·진행·복습 제외·최근 결과를 비우고 16점·측정 0개로 되돌린다. 설정과 즐겨찾기를 유지하며 저장 실패·탭 충돌 시 기존 기록을 보존한다.
- 변경된 프로필·세션·undo는 IndexedDB의 단일 트랜잭션에 저장한 뒤 화면에 반영한다. 실패 시 현재 카드·기록을 유지하고, 옛 탭·revision 충돌에서는 덮어쓰지 않는다. 기존 예정일·실패 횟수·완료·undo와 v2 원문을 보존하며 정책 이전은 전체 활성 프로필과 헤더를 함께 저장한다.
- 지원하는 v2/v3 학습 백업은 설정과 학습을 함께 복원하고 실패·중단 복구를 지원한다. 미지원 형식·학습·정책 버전은 쓰기 전에 거부한다. 압축 후 64장 초과 QR은 파일 백업으로 안내한다. 상세 규칙은 [저장·공유](storage-and-share.md)를 따른다.

## 개발 검증·게시 계약

`npm run check:quick`은 타입 검사와 전량 코퍼스 순환·합성 규모 두 파일을 제외한 개발 피드백용 검사다. 생성·콘텐츠 감사·최종 선정 감사가 포함되지 않으며, 원본을 바꾸면 생성과 해당 감사·전체 검증을 실행한다. 검증 범위와 변경 유형별 필수 항목은 [검증 규칙](testing-rules.md)을 따른다.

Pages CI는 `npm run check:release`로 빌드 → 전체 테스트 → 콘텐츠 감사 → `jlpt:audit -- --require-target`을 통과한 버전만 게시한다. 빌드의 사전 생성·JLPT 감사와 기존 검사 범위·시간 제한·작업자 2개를 유지한다. 순수 로직 검사는 Node 환경, DOM 검사는 기본 JSDOM 환경에서 실행한다. 릴리스 매니페스트 작성·업로드·배포는 검증 이후 별도 단계다.

`release.json`의 commit과 indexSha256로 실제 공개 버전과 HTML을 대조한다. 로컬 검증이나 콘텐츠의 published 원장은 웹 게시 성공을 뜻하지 않는다. 사용자가 요청한 완료 후 Git push → 실제 게시 확인 → 비강제 컴퓨터 종료 순서는 해당 요청이 있을 때 따른다. 기존 큰 번들 경고와 실제 휴대폰·Safari 검증 범위는 별도로 남아 있다.

2026-10-06 유지보수 최적화의 구현 범위·검증 상태와 후속 제안은 [유지보수 계획](../plans/maintenance-efficiency.md)을 따른다. 과거 테스트 개수·브라우저 측정과 게시 실패 기록은 이력에 보존하며 현재 검증 실행 결과를 대신하지 않는다.
