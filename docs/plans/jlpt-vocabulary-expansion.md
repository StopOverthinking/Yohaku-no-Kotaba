# N5~N1 실용 어휘 확충 계획

작성: 2026-09-29. 상태: 구현 중. 검토한 콘텐츠를 단계적으로 로컬 앱에 반영 중이며 전체 수량·전량 성능 검증·배포는 미완료. 상세 현황은 [작업 원장](../../content/jlpt/README.md)과 [진행 집계](../../content/jlpt/progress.json)를 따른다.

## 1. 목표와 수량 기준

N5~N1 다섯 수준별 단어장을 제공한다. **2026-09-30 사용자 변경: 1만 개는 어림값이며 실용성이 떨어지면 목표 수를 자체적으로 줄인다.** 이전 총 12,000개·신규 10,000개 하한은 폐기한다. 약 6,000~8,000개를 잠정 검토 범위로 삼되, 이 범위도 할당량이나 완료 기준이 아니다. 생활·직장·일반 독해·사회·문화 어휘의 수준별 누락과 미선정 후보의 효용을 독립 검토한 뒤 실제 최종 수량을 확정한다. 모든 수록 어휘에 문맥 회상 학습에 필요한 의미·힌트·혼동 표현·예문을 완성한다.

| 단어장 | 주요 범위 |
| --- | --- |
| N5 | 사람·가족·시간·음식·위치·기초 행동·일상 표현 |
| N4 | 학교·주거·이동·건강·약속·감정·생활 절차 |
| N3 | 직장·관계·서비스·사건·의견·일상적인 설명 |
| N2 | 사회·경제·환경·업무·보도·추상적인 판단 |
| N1 | 논설·정책·문화·학술적 일반어·정교한 뉘앙스·관용 표현 |

수준별 고정 할당량을 두지 않는다. 숫자를 맞추려고 드문 전문어·인명·지명·활용형·기계적 파생어를 채워 넣지 않는다. 상위 단어장에 하위 단어를 복제하지 않는다. 기존에 검토한 실용 어휘·추가 예문을 수량 축소를 이유로 일괄 삭제하지 않는다.

현재 원본을 직접 집계한 기준값은 기본 단어장 3개, 단어 행 1,508개, 용법 1,508개, 예문 3,016개다. NFKC 정규화 표기+읽기의 고유 조합은 1,385개다. 이 값은 의미까지 판정한 최종 중복 제거 수가 아니며, 동형이의어·표기 변이·품사 차이는 별도 대조한다. 현재 예문 난도는 10~59다.

신규 수는 실행 시작 시 고정한 기존 어휘 목록과 계속 대조한다. 기존 재사용을 신규로 세지 않으며, 최종 보고에는 전체 행 수, 고유 어휘 수, 기존 재사용 수, 신규 수, 중복·제외 수를 구분한다. `content/jlpt/scope.json`에 현재 선정 기준을 기록한다. 최종 선정 검토는 수준별 범위 설명·확정 수량·현재 게시 원장 해시에 연결하며, 단순히 잠정 수량에 도달했다고 완료로 판정하지 않는다.

## 2. 수준 분류와 어휘 선정

JLPT는 현행 시험의 어휘·한자·문법 전체 목록을 공개하지 않는다. 따라서 N5~N1은 공식 보증 표기가 아니라 앱의 권장 학습 수준으로 설명한다. 공식 수준별 언어 활동 설명을 기준으로 기초성, 사용 범위, 추상성, 문어성 및 문맥 난도를 함께 판단한다. [JLPT FAQ](https://www.jlpt.jp/e/faq/), [공식 수준 설명](https://www.jlpt.jp/e/about/levelsummary.html).

1. 재사용 가능한 사전에서 약 15,000~18,000개 후보를 확보한다. 표제어·읽기·품사·활용·의미 식별을 먼저 정리한다.
2. 수준별 후보 목록은 재사용 조건이 명확한 자료만 채택한다. 각 자료의 출처·버전·분류 근거를 보존하며, 출처별 등급 충돌은 검토 대기열에 넣는다. 실행 단계에서 실제 파일과 이용 조건을 확인하기 전에는 특정 공개 목록을 확정 자료로 취급하지 않는다.
3. 품사와 생활 영역의 분포표를 만든다. 현재처럼 동사에 편중되지 않도록 명사·형용사·부사·접속 표현·관용 표현·의성어/의태어를 함께 다룬다. 고정 비율을 맞추기 위한 저품질 항목은 추가하지 않는다.
4. 각 단어에 권장 수준, 근거, 확신도, 검수 상태를 기록한다. 수준을 판정하지 못한 항목은 공개 수량에 포함하지 않는다.
5. 대표 용법으로 기본 수준을 정하되 어려운 파생 의미는 별도 용법 수준을 가진다. N5 단어의 고급 용법이 N5 학습에서 갑자기 나오지 않게 한다.

표제어·읽기·품사 정보의 우선 후보는 JMdict다. 사용 시 원본 릴리스와 항목 ID, 변경 내역, 출처 고지 및 파생 데이터의 이용 조건을 함께 관리한다. 현행 EDRDG 고지는 CC BY-SA 4.0 및 갱신 절차를 명시한다. 한국어 뜻과 예문은 직접 작성하고, 사전에서 파생된 부분은 해당 조건에 맞게 표시한다. 사전 갱신 차이는 검토 후 반영하며 검수된 문장을 자동으로 덮어쓰지 않는다. [EDRDG 이용 조건](https://www.edrdg.org/edrdg/licence.html).

## 3. 단어장 구성과 기존 기록

- 새 수준별 ID는 `jlpt-level-n5`~`jlpt-level-n1`로 고정한다. 기존 `jlpt-n3`와 충돌하지 않는다. UI는 `N5`, `N4`, `N3`, `N2`, `N1`과 개수 중심으로 구성한다.
- 기존 세 단어장은 명시적인 삭제 요청이 없으므로 유지한다. 새 수준별 단어장은 어휘 ID의 목록을 참조하는 별도 분류로 제공한다. 같은 단어의 내용을 새 ID로 복사하지 않는다.
- 현재 `setId` 하나로 소속을 판정하는 코드와 에디터의 재정규화가 수준별 참조를 지우지 않도록, 기존 소유 세트와 수준별 목록을 구분한다. 수준별 목록 조회는 `wordIds`의 순서를 기준으로 한다. 에디터·xlsx·생성 스크립트까지 같은 관계를 보존한다.
- 신규 어휘 ID는 수준·정렬 번호에 의존하지 않는 안정적인 ID를 사용한다. 수준 변경으로 단어·용법·예문 ID를 재발급하지 않는다.
- 기존 단어장끼리 겹치는 항목은 대표 ID와 별칭 목록을 작성한다. 수준별 목록과 고유 어휘 집계에서는 대표 항목만 포함한다. 기존 ID·프로필은 일괄 삭제하거나 합산하지 않는다.
- 별칭에만 학습 기록이 있는 경우 대표 항목에서 기록을 이어받을 수 있도록 명시적인 매핑을 제공한다. 복수의 기록이 충돌하면 원본을 모두 보존하고, 복습일은 더 이른 날짜·숙련도는 더 보수적인 단계로 결정하는 규칙을 테스트한다. 점수 측정 이력은 중복 가산하지 않는다. 진행 세션은 기존 ID로 끝낼 수 있도록 호환 조회를 유지한다.
- 수준별 목록 순서는 확정 후 안정적으로 유지한다. 새 단어는 뒤에 추가하고, 기존 숫자 범위·필수 범위가 다른 단어를 가리키는 재정렬은 하지 않는다. 수준 이동 등 순서 변경이 필요한 릴리스에서는 범위 설정의 재확인 상태를 명시한다.
- 앞서 삭제한 주제별·비슷한 단어장은 다시 만들지 않는다. 혼동 표현은 각 용법의 힌트·차이 설명으로 제공한다.

## 4. 모든 단어에 채울 데이터

| 계층 | 필수 내용 | 완료 조건 |
| --- | --- | --- |
| 단어 | 안정적 ID, 표기, 읽기, 한국어 핵심 뜻, 품사, 수준, 출처 | 오표기·누락·불필요한 중복 없음 |
| 문법 | 동사 그룹·자타 구분, 필요한 사용 제약, 대표 결합 표현 | 적용되는 항목은 모두 작성, 비해당은 명시 |
| 용법 | 용법 ID·버전, 구체적 의미, 수준, 한국어 힌트, 혼동 표현과 차이 | 단어별 최소 1개, 중요한 다의어는 2개 이상 |
| 예문 | 예문 ID·버전, 앞문장/정답/뒷문장, 활용형 읽기, 한국어 번역·강조 구간, 난도 | **용법별 대표 예문 최소 1개, 쓰임 구별에 필요한 경우 추가** |
| 검수 | 작성·검수 상태, 검토자/검토 방법, 시각, 수정 사유, 콘텐츠 해시 | 수정 뒤 이전 검수 표시를 그대로 유지하지 않음 |

2026-09-30 효율 개선: 대표 용법에 좋은 예문 1개를 기본으로 제공하고 다의어나 별도 쓰임에 필요한 경우 추가한다. 기존 2·3개 예문은 보존하며 일괄 세 번째 예문 보강은 중단한다. 12,000개 어휘의 예문 수는 기존 자료와 추가 용법에 따라 달라진다. 별도 용법 수를 단어 수에 더하지 않는다.

예문 선정 기준은 다음과 같으며, 아래 역할마다 의무적으로 한 문장씩 작성하지 않는다.

1. 대표 결합과 의미가 선명한 기본 장면.
2. 화자·상황·문형이 달라져도 같은 의미를 회상할 수 있는 장면.
3. 유의어와 차이 또는 사용 조건이 드러나는 장면.

동일 문장 틀에 단어만 바꾸거나 시제·인명만 바꾼 문장은 독립 예문으로 세지 않는다. 대화·요청·설명·관찰·예상·회고 등의 장면을 섞되, 어휘에 어울리지 않는 다양성을 억지로 만들지 않는다.

N5/N4 문장에서는 목표 단어 외의 어휘와 문법도 기초 수준을 유지한다. N2/N1도 어려운 문어체로만 채우지 않고 실제 사용 상황을 포함한다. 목표 수준을 넘어서는 보조 어휘는 검토 대상으로 표시하고 더 쉬운 표현으로 바꾸거나 꼭 필요한 지원을 제공한다.

정답은 문장에 필요한 활용형 전체를 가린다. 힌트는 한국어 의미·뉘앙스 단서이며 목표 표기·읽기·로마자·음역으로 답을 알려주지 않는다. 한국어 번역은 전체 문장 의미를 자연스럽게 전달하고 강조 구간은 정답의 의미 범위와 일치시킨다. 복수 정답이 자연스러운 문장은 무조건 유일 정답이라고 설명하지 않으며, 문맥을 보강하거나 혼동 표현 설명에 허용 차이를 적는다. 자기평가 학습 방식은 유지한다.

모든 항목에 억지 유의어를 붙이지 않는다. 혼동할 유의어가 없으면 반대 표현, 비슷한 결합, 사용 조건과의 차이를 선정한다. 현 스키마의 `confusions`를 유지할지, 구별 설명 유형을 확장할지는 100개 시범 제작에서 확정하고 빈칸 대신 무의미한 문구를 넣지 않는다.

## 5. 제작·검수 흐름

1. **기준본 고정:** 기존 원본·단어 ID·학습 스키마·원본 해시를 기록한다.
2. **전 수준 시범 제작:** N5~N1 각 20개, 총 100개를 먼저 완성한다. 다의어·자동사/타동사·가나 표제어·부사·관용구를 포함해 빈칸, 힌트, 번역, 검수 형식을 시험한다.
3. **후보 확정:** 표기 변이·의미 중복·실용성을 대조하고, 수준별 누락을 보완하는 후보만 채택한다. 제외 사유와 신규/기존 구분을 기록한다.
4. **25개 단위 인도:** 묶음마다 어휘·용법·예문·검수 기록을 함께 완성한다. 한 번에 거대한 파일을 자동 생성해 검수 완료로 표시하지 않는다.
5. **전량 재검토:** 작성 과정과 분리한 검토에서 일본어 자연스러움, 뜻·읽기, 문맥 회상 가능성, 한국어 번역, 수준을 모든 항목에 대해 확인한다. 자동 또는 AI 검토만 수행한 경우 그 사실을 기록하고 전문가 검수라고 표시하지 않는다. 판단이 어려운 항목은 공개에서 보류하고 대체한다.
6. **묶음 간 대조:** 유의어 집단과 전체 코퍼스의 반복 문형·유사 예문을 다시 확인한다. 이전 묶음과도 비교한다.
7. **수준별 공개본 확정:** 해당 수준의 모든 필수 데이터가 완성된 경우에만 공개본에 포함한다. 초안은 편집용 파일에만 남는다.

구조 검사는 ID·참조·중복·수량·필수값·검수 상태·번역 강조·정답 노출·활용형 읽기·출처를 확인한다. 형태소/사전 대조는 후보를 찾는 수단이고 불규칙 활용·한 글자 단어는 문맥 검토를 병행한다.

유사도 검사는 완전 중복과 가린 문장 중복을 우선 차단한다. 높은 유사도와 반복 도입/결말은 검토 목록으로 출력한다. 공통된 정상적인 문법을 모두 오류로 취급하지 않으며, 예외 승인에는 이유를 남긴다. 미해결 검토 항목이 있는 묶음은 완료 처리하지 않는다.

작업량은 100개 시범에서 작성 시간, 검수 시간, 재작성률을 측정해 산정한다. 전체 예상 시간은 `남은 묶음 수 × 검수 완료 묶음당 실측 시간 + 통합 검증 시간`으로 갱신한다. 검수 없이 수만 문장을 즉시 완성할 수 있다고 전제하지 않는다.

## 6. 대용량에서도 원활하게 학습하기 위한 구현

현재 확인한 병목은 전체 예문 정적 import, 전역 콘텐츠 준비 판정, 다음 항목 선택의 전체 후보 정렬, 매 조작의 전체 localStorage 직렬화, 예문 감사의 전체 쌍 비교다. 현 원본 예문 파일은 약 2.07MB이며 예문 36,000개는 문장 길이에 따라 크게 증가한다. 단순 비례치와 실제 압축·메모리 사용량은 구분한다.

### 콘텐츠 로딩

- 가벼운 단어·용법·난도·검수 상태 인덱스와 예문 본문을 분리한다. 예문은 수준별 및 200개 내외 묶음으로 나누고 해시가 있는 manifest로 관리한다.
- 시작할 단어장과 현재/다음 카드에 필요한 묶음을 읽고 다음 묶음을 미리 가져온다. 전체 자동 추천은 메타데이터를 사용해 기존 복습 우선 정책을 유지한다.
- 콘텐츠가 아직 로딩되지 않은 상태와 데이터 오류를 구분한다. 로딩 실패 시 기존 기록을 지우지 않고 재시도한다. 새 버전과 옛 캐시를 섞지 않도록 manifest 버전을 세션에 고정한다.
- 새 브라우저의 초기 수준은 현재와 같은 난도 기준으로 계산하되, 로딩된 일부 묶음만으로 전체 중앙값을 잘못 계산하지 않는다. 기존 사용자의 수준 값은 보존한다.
- 초안 한 개 때문에 정상 단어장 전체가 막히지 않도록 공개 manifest를 완성된 데이터만으로 생성한다. 불완전한 공개본은 빌드 단계에서 차단한다. 실행 중 누락 발견 시 해당 범위를 명시적으로 차단하고, 조용히 출제 개수를 줄이지 않는다.

### 출제·목록·에디터

- 단어/용법/예문 ID와 단어장 범위 인덱스를 만든다. 매 응답의 전체 정렬을 필요한 후보 선택으로 줄이되 복습일·실패 횟수·필수 범위·동률 무작위 규칙을 동일하게 유지한다.
- 예문 난도는 단어장 등급과 구분한다. 기존 10~59 난도와 맞닿는 공통 기준 예문을 먼저 정하고 새 난도를 보정한다. N1이라고 기계적으로 최고 난도를 부여하거나 사용자 점수를 JLPT 합격 등급으로 변환하지 않는다.
- 단어 목록과 복습 목록은 대용량 렌더링을 제한한다. 가상 목록 또는 페이지 단위 표시를 실제 스크롤 복원·검색·가리기·즐겨찾기 동작과 함께 검증한다.
- 데스크톱 에디터는 현재 20개 용법 단위 예문 편집을 유지하고, 단어 표와 파일 입출력도 묶음 단위로 처리한다. 편집 원본→생성 데이터→xlsx 왕복에서 ID·순서·수준·검수·출처가 보존되어야 한다.
- 전체 예문 유사도 검사는 해시 중복 검사와 n-gram 역색인/후보 축소를 사용한다. 36,000문장의 약 6.48억 쌍을 매번 전수 비교하지 않는다. 작은 기준 코퍼스의 전수 비교 결과와 대조해 누락률을 평가한다.

### 저장·백업

- 12,000개 이상의 누적 학습 프로필과 장시간 undo를 고려해 학습 기록은 전용 IndexedDB 저장 계층으로 옮기는 것을 기본안으로 한다. 작은 환경 설정은 localStorage에 유지한다.
- 한 응답에서 변경한 프로필·세션·undo·revision을 하나의 트랜잭션으로 저장하고 성공 후 화면을 진행한다. 다중 탭 충돌, 용량 초과, 브라우저 종료 중 쓰기를 시험한다.
- 기존 `jsp-react:context-learn-v2`를 읽어 새 저장소에 쓴 뒤 재조회·대조한다. 성공 확인 전에는 원본을 제거하지 않는다. 마이그레이션은 재시도 가능하고 중복 실행에 안전해야 한다.
- 백업은 localStorage 열거에만 의존하지 않도록 확장한다. 기존 v2 백업을 계속 읽고, 새 저장소의 프로필·세션·undo를 모두 파일 백업/복원에 포함한다. 복원은 원자적으로 처리한다.
- QR의 대용량 한계를 실측하고 압축 후 프레임 수가 지나치면 파일 백업 경로를 제공한다. 성공적으로 내보내지 않은 데이터를 백업 완료로 표시하지 않는다.

## 7. 검증과 공개 기준

다음 수치는 구현 후 실측할 **목표**이며 현재 달성한 결과가 아니다.

| 영역 | 완료 기준 |
| --- | --- |
| 어휘 | 실용적 N5~N1 범위 및 미선정 후보 검토 완료, 최종 선정 근거·수량 독립 승인, 고정 최소 수량 없음 |
| 콘텐츠 | 모든 공개 단어에 검수 용법, 용법마다 1개 이상 검수 예문, 필수값 누락 0 |
| 품질 | 오역·읽기·참조·정답 노출 등 확인된 오류 0, 미해결 검토 항목 0 |
| 출제 | 모든 공개 용법과 예문이 후보가 될 수 있음, 수준·범위 밖 출제 및 의도하지 않은 중복 없음 |
| 기록 | 기존 프로필·예정일·점수·진행 세션 보존, undo·재학습·다중 탭·백업 왕복 통과 |
| 성능 | 고정한 모바일 기기/에뮬레이션 조건에서 카드 조작→다음 표시 p95 100ms 이내, 검색 반영 p95 200ms 이내 |
| 시작 | 네트워크 조건을 기록하고 선택한 학습 첫 문제 표시 2초 이내 목표; 최초/캐시 재방문을 별도 측정 |
| 규모 | 최종 실제 단어·예문·전량 학습 프로필 및 500회 판정/undo 부하에서 데이터 유실·저장 실패 없음. 12,000단어/36,000예문 합성 부하 결과는 여유 용량의 별도 근거 |
| 배포 | 전체 테스트·빌드·새 브라우저 및 기존 기록 브라우저 확인 후 공개, 이전 콘텐츠 manifest로 되돌릴 수 있음 |

자동 검증은 N5~N1의 모든 ID를 대상으로 최소 한 번 세션 후보와 공개/판정 경로에 통과시킨다. 각 용법에 있는 모든 예문이 선택 가능함을 확인한다. 실제 브라우저에서는 각 수준의 대표 항목을 데스크톱 키보드·모바일 터치·새로고침·백그라운드 복귀로 확인한다. 사용자 범위 선택에 따라 자연스럽게 제외되는 항목과 버그로 영구 출제되지 않는 항목을 구분한다.

성능 측정은 동일 기기·브라우저·네트워크에서 최초 로드와 재방문을 나누고 여러 회 실행해 p95를 기록한다. 한 번 빠르게 동작한 결과로 통과시키지 않는다. 콘텐츠 수량을 줄여 성능 기준을 맞추지 않는다.

## 8. 실행 순서와 산출물

1. 기준본·후보·출처·등급 정책 확정 → 어휘 목록, 중복 대조표, 신규 수 집계, 출처 목록.
2. 100개 시범 제작 및 전 흐름 검증 → 작성 규칙, 검수 양식, 실제 작업량 추정.
3. 분할 로딩·인덱스·저장·백업·에디터 기반 구현 → 기존 기록 호환 테스트와 12,000개 규모 부하 결과. 성능용 합성 데이터는 공개 콘텐츠에 섞지 않는다.
4. 수준별 묶음 제작·전량 검토 → 수준별 공개 후보, 검수 및 수정 기록. 최신 사용자 지시에 따라 GPT-6.1 Sol medium 두 담당이 서로 다른 어휘 묶음의 단어·예문을 함께 작성하고, GPT-6 Astra high가 검토·문제 수정을 담당한다. 기본 25개 단위로 넘기고 검토 완료분만 반영한다. 예문은 대표 1개를 기본으로 하되 중요한 별도 쓰임에는 추가한다.
5. 전체 유의어·난도·예문 다양성 대조 → 수량·누락·중복·참조·검토 결과 보고서.
6. 전체 학습 회귀·기기별 성능·마이그레이션·백업 검증 → 릴리스 후보와 되돌리기 절차.
7. 공개 후 해당 위키를 실제 구현에 맞게 갱신 → `vocab-data`, `learn-mode`, `editor`, `list-mode`, `storage-and-share`, `architecture`, `testing-rules`, `current-state`.

첫 구현 단위는 **100개 시범 콘텐츠와 데이터 검증 경로**다. 품질 기준과 호환 동작을 확인한 다음 대량 제작을 시작한다. 이 문서 작성 자체는 구현·배포 완료를 의미하지 않는다.
