# JLPT 어휘 환산 안정화 계획

작성: 2026-11-06. 상태: 11/6 안정화와 11/9 과거 기록 재추정 구현·로컬 검증 완료. 공개 게시 버전은 release.json과 배포 실행 결과로 확인한다. 현재 동작 계약은 [학습 위키](../wiki/features/learn-mode.md)를 따른다.

## 목표와 범위

문제 추천에 쓰는 빠른 점수와 JLPT 표시에 쓰는 완만한 추정치를 분리한다. 측정 완료 후 한 응답의 JLPT 표시 변화는 최대 0.1등급으로 제한하고, 지속적인 실력 변화에는 여러 응답에 걸쳐 따라간다.

현재 `level.value`, 문제 선택, 복습 간격, 하루 첫 판정, 힌트·공개 정책을 유지한다. JLPT 경계 19·26.5·33.5·41·49.5점과 65% 예상 회상 기준, N5.9~N1.0 표시 범위도 유지한다. 이번 작업은 안정화이며 환산 경계의 타당성을 새로 입증하는 작업은 아니다.

## 1. 계산 방식

- 기존 추천 점수: 초기 20단어 K=8, 이후 K=2를 유지한다.
- 별도 JLPT 추정치 `E`를 만들고 측정 완료 후 K=0.25로 갱신한다.
- `p = 1 / (1 + exp((difficulty - E) / 8))`
- `E_next = E + 0.25 * (known - p)` (앎=1, 모름=0).
- `p`는 추천 점수가 아닌 **갱신 전 JLPT 추정치**로 계산한다. 맞히면 상승·틀리면 하락하는 방향을 보장한다.
- 추천 점수의 이동 평균은 사용하지 않는다. 추천 점수가 추정치보다 낮을 때 맞혀도 표시가 하락하는 현상을 피한다.
- 내부 실수는 반올림하지 않고 저장한다. 기존 `jlptEstimate`의 경계·선형 환산·표시 올림만 마지막에 적용한다.
- 계수는 누적 학습량에 따라 0으로 줄이지 않는다. 오랫동안 학습한 사용자도 변화에 적응할 수 있어야 한다.
- 같은 용법·같은 날 첫 판정만 반영한다. 같은 날 재학습은 추정치에 추가 반영하지 않는다.

현재와 같은 추정치에서 비교하면 한 응답의 갱신 강도는 기존의 1/8이다. 한 번의 변화는 내부 점수 0.25 미만이며, 가장 좁은 등급 간격 7점보다 충분히 작아 표시 이동이 최대 한 칸(0.1)이다. 경계 근처의 0.1 변화까지 없애는 정책은 이번 범위에 포함하지 않는다.

예: 시작 30점·N3.5, 예상 정답률 75%인 동일 문제.

| 판정 | 현재 직접 환산 | 제안한 별도 추정치 |
| --- | --- | --- |
| 앎 | 30.5점 · N3.5 | 30.0625점 · N3.5 |
| 모름 | 28.5점 · N3.8 | 29.8125점 · N3.6 |

위 예는 계산 확인값이며 실제 사용자 데이터 측정값이 아니다.

## 2. 최초 측정과 기존 기록

- 새 사용자는 20개 서로 다른 대표 단어의 초기 측정을 유지한다. 그 전에는 JLPT 표시를 숨긴다.
- 20번째 단어를 판정한 **후**의 추천 점수로 추정치를 한 번 초기화한다. 같은 판정을 K=0.25로 다시 반영하지 않는다.
- 추정치가 이미 초기화되어 있으면 단어 별칭 정리 등으로 측정 ID 개수가 달라져도 재초기화하거나 숨기지 않는다.
- 2026-11-09 사용자 요청으로 기존 기록의 현재 JLPT 값을 한 번 재추정하도록 확장했다. 현재 용법·마지막 예문이 일치하는 프로필의 마지막 학습일 첫 판정·난도를 단어당 합계 1 가중치로 모아 정규화 로지스틱 일괄 추정한다. 유효 20단어 미만이면 기존값을 유지한다. 전체 과거 응답 순서나 누적 실패/노출을 가짜 응답열로 재생하지 않는다.
- 진행 세션·undo가 없는 안전한 경계에서 한 번 전환한다. 진행 중인 구형 세션은 기존 계산·undo로 마친 뒤 완료 또는 파기 경계에서 전환한다. 전환을 위해 진행 세션을 지우지 않는다.
- 일회성 과거 기록 재추정에서 현재 등급은 바뀔 수 있다. 그 후 유효 판정부터 완만한 갱신과 단일 응답 0.1등급 상한을 따른다.
- 초기화는 새 추정치도 미측정 상태로 되돌린다. 복습 목록 삭제는 기존처럼 점수와 추정치를 보존한다.

## 3. 저장·호환성

- 학습 상태 스키마를 `version: 4`로 확장한다. 복습 정책의 `scheduleVersion: 4`는 별개의 값이며 간격 정책은 바꾸지 않는다.
- 새 상태에 `jlptEstimate: { policyVersion: 1, value: number | null }`을 저장한다. `null`은 초기 측정 미완료다.
- 새 상태의 모든 undo에도 판정 직전 추정치를 저장하고 함께 복원한다. 상태·프로필·세션·추정치를 기존 단일 트랜잭션으로 저장한다.
- 완료 결과·최근 점수 변화에 선택적 JLPT 전후값을 추가한다. 전후값은 각 시점에 실제 저장된 추정치이며 측정 전 값은 `null`이다.
- v2/v3 백업 읽기를 유지하고 안전한 경계에서 v4로 이전한다. 이미 진행 중인 구형 세션이 담긴 백업도 같은 경계를 따른다.
- 구형 앱은 v4 학습 상태를 거부하므로 새 필드를 모르고 덮어쓰지 못한다. 알 수 없는 추정 정책 버전·비정상 숫자·필수 추정치가 없는 v4는 쓰기 전에 거부한다.
- IndexedDB 이름·외부 백업 키·프로필 저장소는 유지한다. 헤더가 이미 상태 본문을 저장하므로 새 테이블을 추가하지 않는다.
- `contextAliases`의 현재 `version: 3` 대입이 v4를 낮추지 않도록 바꾼다. v4에서도 별칭 원본·용법 분리 원본을 검증·보존한다. 역사적 보관 원본에 추정치를 소급 생성하지 않는다.
- 저장 실패·탭 충돌에서는 이전 값과 화면을 유지한다. 이전 실패 시 재시도하며, 반복 로드로 초기값을 다시 덮어쓰지 않는다.

## 4. 화면

- 홈의 점수 칸은 기존 추천 점수를, JLPT 칸은 별도 추정치를 표시한다. 새 칸·배지·상시 설명을 추가하지 않는다.
- 결과 화면의 점수 증감은 기존 값, JLPT 전후는 추정치 스냅샷을 사용한다. 등급이 같으면 하나만 표시한다.
- 해당 세션에서 처음 측정이 끝났다면 JLPT 이전값 없이 결과 등급 하나만 표시한다.
- 과거 완료 기록에 JLPT 스냅샷이 없으면 추천 점수로 새 정책의 전후값을 만들어 내지 않는다. 이용 가능한 현재 등급만 표시한다.
- 기존 화면과 v2 화면에 같은 조회 함수를 적용한다. 접힌 규칙 안내만 두 값의 목적에 맞게 짧게 수정한다.

## 5. 구현 순서

1. 순수 추정 갱신 함수·정책을 추가하고 단일 응답 상한과 지속 변화 적응을 검증한다.
2. 상태/undo/결과 타입, 파서·직렬화·DB·백업·안전한 이전을 구현한다. 별칭·용법 분리와 v4 호환을 먼저 확인한다.
3. 엔진의 기존 하루 첫 판정 경계에 추정 갱신을 연결한다. 완료·파기·초기화·undo까지 연결한다.
4. 홈·결과·기존 화면·규칙 안내의 표시 원본을 교체한다.
5. 관련 검사 → `check:quick` → `check:release`, 실제 브라우저의 이전·새로고침·백업 복원·undo·좁은 화면을 확인한다.
6. 구현된 최종 계약에 맞게 `features/learn-mode.md`, `storage-and-share.md`, `current-state.md`, `testing-rules.md`를 갱신한다. 게시와 공개 버전 확인은 별도 단계다.

주요 대상은 `contextTypes.ts`, 새 순수 추정 모듈, `contextEngine.ts`, `contextPersistence.ts`, `contextSerialization.ts`, `contextDatabase.ts`, `contextAsyncStore.ts`, `contextAliases.ts`, 공유 백업 경로, `jlptEstimate.ts`와 두 화면 계층이다. 어휘 원본을 바꾸지 않는다.

## 6. 통과 기준

- 초기화 이후 어떤 한 판정도 표시를 0.1등급 넘게 움직이지 않는다. 경계 전후와 N5.9/N1.0 제한을 함께 검사한다.
- 정답은 내부 추정치를 내리지 않고 오답은 올리지 않는다. 같은 날 재판정·힌트·공개만으로 추정치가 움직이지 않는다.
- 같은 응답열을 1회 세션 또는 여러 세션으로 나누어도 최종 추정치는 같다. 세션 완료 때만 일괄 갱신하지 않는다.
- 추천 점수·카드 선택·복습일·완료 시점은 변경 전 엔진과 동일하다.
- undo→재판정, 새로고침, v4 백업 왕복에서 두 점수·JLPT 전후값이 일치한다. 옛 진행 세션의 이전은 연속 undo를 보존한다.
- v2/v3 이전의 반복 실행·중단·실패·탭 충돌·알 수 없는 버전 거부를 검사한다. 초기 측정 완료 전후·별칭 연결·용법 분리·삭제·초기화를 포함한다.
- 고정 난수의 합성 응답열로 동일 실력에서의 변동 폭과 지속 상승/하락 시 적응 속도를 비교한다. 안정 구간의 내부 점수 표준편차를 기존 대비 50% 이상 줄이는 것을 목표로 한다. N1/N5 제한에 의한 가짜 안정은 제외한다.
- 적응 속도는 기대 응답값을 사용하는 별도 모형에서 확인한다. 시작 30점에서 실제 능력을 37.5 또는 22.5로 바꾸고, 기존 추천 점수가 고르는 예상 정답률 75% 난도의 문제를 계속 푸는 조건에서 200판정 안에 변화량 절반 이상을 따라가야 한다. 이 모형은 응답의 무작위성을 제거한 계산 확인용이며 실제 사용자 적응 시간으로 해석하지 않는다.

계수 0.25의 사전 계산에서 위 기대값 모형은 200회 뒤 각각 35.37점·25.11점으로 이동해 절반 추종 기준을 충족했다. 구현 검사에서 고정 난수 8개 응답열 모두 표준편차 절반 이하 목표를 충족해 계수 0.25를 유지했다.


## 7. 구현·검증 결과 (2026-11-06)

- 별도 순수 모듈 `jlptLearningEstimate.ts`, 학습 상태 v4, undo/결과 스냅샷, 안전한 기존 기록 이전, 홈·결과·기존 화면 연결을 구현했다. 새 테이블·백업 키·전체 행동 로그는 추가하지 않았다.
- 기존 저장·백업 계층의 상태 본문 전달을 그대로 활용하므로 `contextSerialization.ts`, `contextDatabase.ts`, 공유 조정 계층의 운영 코드는 수정하지 않았다. 왕복·실패 검사는 새 필드까지 포함한다.
- 초기화는 별칭 정리보다 먼저 수행한다. 기존 20단어 측정 ID가 별칭 중복 제거로 19개가 되어도 현재 등급을 유지한다. 구형 진행 세션의 완료·파기 저장 실패와 재시도도 확인했다.
- `check:quick`: 타입 검사와 60개 파일·402개 검사 통과. 이후 기존 측정 ID 중복 제거에 대한 회귀 검사 1개를 추가했다.
- 최종 `check:release`: 빌드, 62개 파일·436개 전체 검사, 콘텐츠 감사, `jlpt:audit -- --require-target` 통과. 콘텐츠 누락 0·주변 한자 노출 0이며 생성 어휘의 의미 변경은 없다. 기존 큰 번들 경고는 남아 있다.
- 실제 Chromium 격리 세션에서 v2 백업을 앱 백업 경로로 복원하고 v4 이전을 확인했다. UI 오답 후 추천 점수 30→28.490170, 추정치 30→29.811271을 같은 IndexedDB에 저장하고, 새로고침 후 이전 카드로 두 값 모두 30으로 복원했다. 앱 백업 내보내기→복원에서 추정치와 undo를 보존했다.
- 같은 날 재학습 정답 이후 결과·홈은 N3.5→N3.6을 표시했고 추정치는 추가 변동하지 않았다. Chromium 375×812 화면에서 결과·홈의 가로 넘침이 없었고 콘솔 오류/경고 0개를 확인했다. 실제 휴대폰·Safari 검증은 포함하지 않는다.
- 위키의 학습·저장·현재 상태·검증 계약을 갱신했다. Git push와 공개 게시 확인은 수행하지 않았다.


## 8. 2026-11-09 과거 기록 재추정 확장

사용자가 과거 기록으로 현재 JLPT 값을 다시 추정하는 방식을 선택했다. 원래 계획의 현재 추천 점수 복사 방식에서 위 2절과 학습·저장 위키의 일괄 추정 방식으로 변경한다. 이번 일회성 변화에는 단일 응답 0.1등급 상한을 적용하지 않는다.

- 현재 활성 프로필만 근거로 사용하고 용법/예문이 없으면 난도를 추측하지 않는다. 완료·제외된 단어의 보존 기록은 포함하고 별칭/의미 분리의 보관 원본은 중복하지 않는다.
- 대표 단어별 가장 최근 학습일의 첫 판정만 사용한다. 같은 날 남은 여러 용법은 가중치를 나누고 순서를 만들지 않는다. 평균 16·표준편차 8의 정규 사전분포로 전부 앎/모름과 적은 표본의 발산을 막는다.
- 기존 측정 ID가 중복 제거로 20개 아래가 되었어도 유효 20단어 이상의 현재 기록이면 재추정할 수 있다. 유효 기록 부족 시 기존값을 유지한다.
- 일회성 표시 `jlptHistoryReestimate`를 현재 추정치와 원자적으로 저장한다. 초기 v4에도 표시가 없으면 한 번 적용하고 새 사용자·초기화는 처음부터 0개 표시를 가져 중복 재추정을 하지 않는다. 구형 진행 세션·undo는 종료 전까지 그대로 유지한다.
- 완료 경계 재추정은 실제 종료 추정치를 결과/최근 변화에도 함께 기록한다. 저장 실패·탭 충돌·백업 왕복은 적용 표시와 값을 함께 보호한다.


### 11/9 최종 검증

- 개발 검사: 타입 검사와 61개 파일·417개 검사 통과. 최종 전체 검사: 63개 파일·450개 검사, 빌드, 콘텐츠 감사와 최종 JLPT 감사 통과. 기존 큰 번들 경고 외 추가 빌드 경고는 없다.
- 실제 Chromium 격리 세션에서 현재 예문 난도가 일치하는 합성 과거 기록 60단어를 v2 앱 백업으로 복원했다. 추천 점수 45는 유지하고 JLPT 추정치는 34.38871185121016점(N2.9)으로 재추정되었으며, 적용 표시의 단어 수는 60이었다. 실제 사용자 기록의 결과가 아니다.
- 앱 백업 왕복·새로고침 뒤 같은 값과 적용 표시를 보존했다. 이후 UI 오답 한 번은 추정치만 34.23025981071173점으로 완만하게 갱신했고, 새로고침 뒤 이전 카드로 34.38871185121016점을 복원했다. 당일 재학습 후 결과는 N2.9→N3.0이었다. 콘솔 오류·경고 0개, 375×812 결과 화면을 확인했다.
- 진행 중인 세션은 완료·닫기 경계에서, 그 외 기존 기록은 새 버전 부팅 시 한 번 적용한다. 한 번 재추정할 때 등급이 바뀔 수 있다. 기록이 부족한 경우에는 기존값을 유지한다.
