# 유지보수·개발 효율 최적화 계획

작성 기준: 2026-10-06

## 2026-10-06 개발 검증·탐색 비용 정리

기존 후속 제안 1·2의 검증 명령 표준화와 위키 현재 계약/이력 분리를 구현했다. 이 범위의 계획·독립 검토는 GPT-6 Astra high, 코드·문서 수정은 GPT-6.1 Sol high가 담당한다. PR 전용 워크플로·브라우저 반복 실행 기반·생성 캐시는 이번 범위에 포함하지 않는다.

| 적용 | 효과와 유지할 계약 |
| --- | --- |
| `typecheck`, `test:quick`, `check:quick` | 타입과 일상 회귀 피드백을 별도 실행한다. 빠른 검사는 기본 전체 Vitest 구성에서 `jlptPilot.test.ts`·`contextScale.test.ts` 두 파일만 제외하며 개발용/제외 범위를 출력한다. 생성·감사·게시 완료를 대신하지 않는다. |
| `check:release`와 Pages CI 공유 | 빌드 → 전체 테스트 → 콘텐츠 감사 → 최종 선정 감사의 기존 순서를 하나의 명령으로 유지한다. `prebuild` 생성·JLPT 감사와 매니페스트·업로드·배포 단계를 보존한다. |
| 순수 검사 17파일의 Node 환경 지정 | `scripts/lib` 14파일과 복습 정책·전량 순환·합성 규모 3파일에서 불필요한 DOM 환경 초기화를 줄인다. 기본 JSDOM, 작업자 2개, 기존 시간 제한·전량 검사·이벤트 루프 양보를 유지한다. |
| 현재 계약과 과거 기록 분리 | [현재 상태](../wiki/current-state.md)를 기능·집계·저장/게시 계약·우선순위로 축약하고 [기존 원문](../wiki/current-state-history-2026-10-06.md)은 날짜 이력으로 그대로 보존한다. 원문과 같은 디렉터리에 두어 상대 링크를 유지한다. |
| 문서 우선 탐색·검증표 | 위키 → 관련 코드 → 관련 테스트 순서로 읽고 대량 원본·생성·승인 자료는 정확한 ID로 좁힌다. [검증 규칙](../wiki/testing-rules.md)에 빠른/전체 범위와 변경 유형별 필수 검증을 명시한다. |

집계 확인에서 현재 선택 가능한 기본 단어장은 2개이며 `AbsoluteVerb`는 보관 상태다. 수준별 현재 5,364개 수록과 과거 4,861개 독립 선정 승인을 구분한다.

동일 장비·Node 24.13.0에서 각 명령을 한 번씩 실행한 결과다.

| 검증 | 명령 경과 | 내부 Vitest | 결과 |
| --- | --- | --- | --- |
| 변경 전 `npm test` | 97.638초 | 96.83초 | 전체 54파일·346검사 통과 |
| 변경 후 `check:quick` | 60.259초 | 48.77초 | 타입 검사와 52파일·313검사 통과 |
| 변경 후 `check:release` | 110.551초 | 89.32초 | 빌드·전체 54파일·346검사·콘텐츠 감사·최종 선정 감사 통과 |

전체 Vitest 시간은 96.83초에서 89.32초로 관측됐다. 단일 실행 비교이므로 Node 환경 전환의 인과 효과나 반복 성능을 보장하지 않는다. 빠른 검사는 범위가 다르며 그 시간으로 전체 검사 속도 향상을 주장하지 않는다. 명령 경과에는 각각 다른 작업이 포함되므로 `check:release` 경과를 변경 전 `npm test` 경과와 직접 비교하지 않는다. 앱·브라우저 성능은 이번 측정 대상이 아니다. 원자료는 로컬 `output/optimization`의 JSON·로그에 보관한다.

최종 선정 감사는 `complete=true`, `issues=[]`, `remaining=[]`다. 콘텐츠·어휘 원본·생성 자료 1,378파일의 전후 SHA-256과 경로가 모두 동일하다. 위키 이력에 보관한 변경 전 원문 24,138바이트도 SHA-256이 일치하며 문서 45개 상대 링크는 모두 유효하다. 외부 게시는 이번 검증에 포함하지 않았다.

아래 2026-10-02 범위는 당시 완료 이력이다. 정책 v3 추출과 그때의 검사 수는 현재 정책 v4·현재 검증 결과를 뜻하지 않는다. 현재 동작은 [학습 계약](../wiki/features/learn-mode.md)과 [저장 계약](../wiki/storage-and-share.md)을 따른다.

## 2026-10-02 사용자 결정 반영

에디터는 더 이상 사용하지 않으므로 구조 개선 대상에서 제외하고 앱 전체를 제거했다. 복습 정책은 기존 동작과 저장 형식을 유지하면서 코드 책임을 분리했다. 이번 코드 작성·수정은 GPT-6.1 Sol high가 담당했다. 아래 이번 적용 범위는 구현·로컬 검증을 완료했으며 후속 제안은 미구현이다.

## 이번 적용 범위

| 작업 | 효과 | 위험과 대응 |
| --- | --- | --- |
| 에디터 앱·라우트·전용 HTML·표 편집·xlsx·파일 권한 처리 제거 | 사용하지 않는 대규모 UI와 관련 의존성·검사·빌드 진입점의 유지 비용 제거 | 단어/예문 원본과 앱 공통 검증까지 함께 지우지 않도록 의존 관계를 확인하고 원본 해시 대조 |
| 에디터와 연결돼 있던 자료 검증을 단어 데이터 영역으로 이전 | 학습 데이터 검증이 폐기한 앱에 의존하지 않음 | ID·소속·참조 순서·예문 연결 검사를 읽기 전용으로 유지 |

| 미지원 백업 오류와 복원 실패 후 대안 제공 | 복원 불가 원인을 알 수 있고 기존 학습을 계속하거나 다른 백업 선택 가능 | 복원 전 거부하며 현재 학습·설정을 변경하지 않음. 학습 부분만 버리는 부분 복원이나 자동 초기화 없음 |

`src/features/vocab/editor-data`는 이름이 남아 있는 단어·예문 JSON 원본 경로다. 학습 앱의 자료 생성·감사와 과거 근거가 이 경로를 사용하므로 유지한다. 에디터 화면·실행 코드의 유지 또는 재도입을 뜻하지 않는다. 원본 수정 후 생성기와 콘텐츠 감사를 실행하는 방식으로 관리한다.

## 복습 정책 위험 판단

실제 복습 규칙이나 저장 스키마를 바꿀 때의 위험은 옛 백업에만 한정되지 않는다. 현재 IndexedDB의 예정일·완료 상태, 진행 세션·undo, 옛 탭의 쓰기도 영향을 받을 수 있다. 따라서 백업 오류 처리만으로 모든 위험이 사라진다고 판단하지 않는다.

이번에는 추가 복습 간격 변경을 하지 않고 기존 v3 정책을 그대로 추출한다. `3 → 7 → 30 → 90일` 정답 흐름, 하루 첫 판정, 오답 초기화, 완료 해제, 기존 예정일과 undo를 보존한다. 지원 중인 v2/v3 학습 백업과 옛 정책 이전은 계속 지원하며, 알 수 없는 형식·정책 버전만 명확하게 거부한다.

복원 실패의 대안은 **현재 데이터로 계속 사용하거나 호환되는 다른 백업을 선택하는 것**이다. 호환되지 않는 입력을 정상 기록으로 추측 변환하지 않는다.

## 검증 완료 기준

1. 에디터 실행 진입점·import·전용 의존성이 없어야 한다. 빌드 결과에도 에디터 HTML·번들이 없어야 한다.
2. 단어 원본, 생성 데이터, 콘텐츠·승인 이력의 변경 전후 해시가 같아야 한다.
3. 데이터 ID·소속·목록 순서·예문 연결 검사와 전체 테스트·타입 검사·빌드가 통과해야 한다.
4. 학습 상태/정책/백업 포맷의 미지원 버전은 복원 전에 거부해야 한다. 현재 DB·설정이 보존되고 이후 호환 백업을 다시 선택할 수 있어야 한다.
5. 예정일·하루 첫 판정·완료·undo·옛 백업 복원 및 저장 충돌/실패 검사가 통과해야 한다.
6. 기존 두 콘텐츠 감사와 최종 선정 검사를 유지한다. 로컬 검증 성공은 외부 게시 완료와 구분한다.

## 후속 최적화 우선순위

이번 결과: 전체 48파일 275검사, 타입 검사·빌드·콘텐츠 감사·최종 선정 감사 통과. 원본 8파일, 생성 데이터 142파일, 콘텐츠·승인 이력 1,220파일의 전후 해시가 동일하다. 실제 브라우저에서 제거한 경로의 홈 이동과 백업 거부·재선택·취소·학습 설정 진입을 확인했다. 외부 게시는 하지 않았다.

## 측정 및 적용 원칙

- 동일 장비·코퍼스에서 초기/재실행 시간을 분리하고 생성·감사·테스트·빌드 비용을 각각 측정한다. 현재 속도 향상률을 추정치로 단정하지 않는다.
- 기존 예문 분할 로딩, 후보 단일 순회, 변경 프로필 저장을 보존한다. 파일 분리 자체를 실행 성능 개선으로 보고하지 않는다.
- 구조 변경은 독립된 작은 검토 단위로 적용하고 해당 위키를 갱신한다. 기존 미커밋 변경은 임의로 되돌리거나 다른 작업에 묶지 않는다.
- 프레임워크·상태 관리·저장소 전면 교체, 모노레포화, 백엔드 신설은 구체적인 필요가 생길 때 다시 검토한다.
- 미니멀·아이콘 중심 UI와 가벼운 시각 효과를 유지한다. 미완 기능인 `탭 매치 러시`는 판단 범위에서 제외한다.
