저장 측정은 실제 앱 스토어·IndexedDB 경로를 개발 서버에서 호출하며 UI 페인트를 제외한다. 501개 세션에서500회 판정→앱 백업 내보내기→전체 복원→hydrate→500회 undo를 수행해 모든 프로필·수준·첫 카드를 원상태와 비교했다. 백업2,459,942byte, 내보내기70.3ms/복원283.9ms/hydrate72.3ms. 전체128개 예문 묶음 로드·검증863.8ms, 누락/불일치/저장 실패 없음.

UI는 배포용 빌드의 실제 버튼을 누르고 MutationObserver로 준비된 다음 문장을 확인한 뒤 두 번의 requestAnimationFrame까지 잰다. 연타 보호 간격300ms 대기는 측정에서 제외했다. 판정50회와 undo50회 후 같은 첫 카드로 복귀했다. 가로 넘침 없음, 브라우저 오류 없음. 검색은 일본어/읽기/한국어20개와 빈 검색20개를 번갈아 입력하고 결과 수·실제 카드 수를 대조한 뒤 같은 방식으로 페인트를 기다렸다.

첫 카드 측정은 임시 HTML에서 동일 배포 번들을 불러오고 원래 학습 경로로 이동하여 문장이 준비될 때까지 측정했다. 새 브라우저5회는 매번 전량 v3 백업을 localStorage에 넣어 IndexedDB 이전까지 포함하며 스크립트/스타일/예문 전송463,418byte를 확인했다. 재방문은 이미 이전된 DB와 HTTP 캐시를 사용해 재검증 헤더 합계1,500byte였다. 둘의 차이는 네트워크 캐시뿐 아니라 최초 DB 이전도 포함한다. 로컬 네트워크 결과이므로 실제 공개망2초 보장을 뜻하지 않는다.

측정 절차 수정 이력: 설정 파일 변경으로 새로고침된 최초 미완료 실행은 제외했다. 초기 undo 비교는 객체 키 순서만 달라 실패했으며 프로필별 비교0건 변경을 확인하고 키 순서와 무관한 비교로 전체500/500을 다시 수행했다. 검색 초기 시도는 잘못 고른 캡션/동일 입력으로 시간 초과됐으므로 관찰 대상과 시작 상태를 고쳐40회 모두 완료했다. 앱 데이터 손실이나 검색 장애로 분류하지 않는다.

도구는 output/playwright/scale-store.js, scale-ui.js, scale-search.js 및 scale-production-seed.js. 프로필은 테스트 브라우저에만 넣었고 실제 사용자 기록은 수정하지 않았다. 임시 시작 HTML은 삭제하며 게시물에 포함하지 않는다. 데이터 확충 후 최종 전체규모에서 다시 검증해야 한다.
